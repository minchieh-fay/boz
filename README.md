# boz 双向波动策略

Go + `github.com/adshao/go-binance/v2/futures` 实现 Binance USDT 永续合约实盘策略。固定连接正式环境，启动后自动交易；没有模拟交易或测试网开关。

## 策略

1. 启动时获取正在交易的 USDT 永续合约，读取限价订单的价格、数量和最小名义金额过滤器。
2. 订阅所有合约的原生 `kline_5m`，通过 REST 初始化历史。按交易所开盘时间维护窗口，`kline_count` **包含当前未收盘 K 线**。例如 12 根是最近 11 根已收盘 K 线加当前区间。区间更新时丢弃最老一根；断线后重连并补齐缺口。不完整、不连续或超过新鲜度限制的窗口不参与选币。
3. 每 `trade_interval_seconds` 秒先查询全账户仓位、普通挂单和条件挂单，再筛选 `(max(high) - min(low)) / min(low) > min_move_rate` 的币种，振幅高的优先。只选择无持仓、无任何挂单、不在冷却期内的币种。
4. 同币连续提交 `BUY + LONG` 与 `SELL + SHORT` 两张 GTX 限价开仓单。REST 请求至少间隔 100ms，因此两边不是交易所原子成交，也无法保证同时成交。
5. 两边共用一个固定数量目标：`trade_usdt / 卖一价` 按 `LOT_SIZE.stepSize` 向下取整；多边挂买一、空边挂卖一。`trade_usdt` 是**每边名义金额**，不会再乘杠杆，两边合计约为两倍配置金额。后续重挂固定数量，实际金额会随价格变化。
6. GTX 明确返回 `-5022` 时向被动方向移动一个 tick，单次最多尝试四次；始终保持 GTX，绝不改成市价或 GTC 开仓。
7. 每 `entry_reprice_seconds` 秒左右核对开仓单。撤单后再次按原订单编号查询最终成交，把撤单竞态期间的成交一起记账，然后只重挂目标的剩余数量。两方向独立推进，先成交的一边不会阻塞另一边。已成交数量不重开、不超额补量；在没有提前退出的正常情况下，最终累计开仓量相同。
8. 发现部分或全部持仓就按实际成本设置全量 `STOP_MARKET`、`TAKE_PROFIT_MARKET` 条件单：`closePosition=true`，不带固定数量和 `reduceOnly`。使用 `CONTRACT_PRICE` 触发，`priceProtect=false`。条件单由交易所托管，触发后市价退出，实际成交价可能偏离触发价。
9. 两边都平仓且所有订单清理完成后记录冷却起点。`max_symbols` 按币计数，同币双向占一个名额；已有仓位、挂单及本地未完成/未知计划都占名额。其他策略或手工交易的占用也计入上限。

每边止盈止损独立计算，触发价按 tick 四舍五入：

| 方向 | 止盈 | 止损 |
| --- | --- | --- |
| LONG | 实际成本 × (1 + take_profit_rate) | 实际成本 × (1 - stop_loss_rate) |
| SHORT | 实际成本 × (1 - take_profit_rate) | 实际成本 × (1 + stop_loss_rate) |

这些比例是价格变动率，不是保证金收益率。一边止盈后另一边继续持仓，整组收益取决于两边最终退出价、手续费和资金费。

## 开仓及异常处理

- 没有主动开仓超时或市价补仓规则；未完成的 GTX 单持续重挂。
- 如果已部分成交单的剩余量不足以重新满足最小数量/最小名义金额，保留原挂单等待，不撤成无法补齐的尾量。若原单已被外部取消而剩余量不能重新挂出，则停止本组补仓并保留已有仓位保护。
- 任一方向在开仓尚未完成时发生减仓，或保护单开始退出，停止本组所有新增开仓并核清剩余开仓单，已有仓位继续由各自保护单处理。这种提前退出情形不再追求补齐双边目标，避免把已经止盈或止损的仓位再次开回来。
- 部分成交改变成本时会按新成本重建保护单。交易所不允许同类全量保护重复存在，因此替换需要先撤旧单；撤旧和新保护确认之间存在短暂空隙。
- 条件单明确被拒绝、保护状态无法确认时，停止新增开仓；原开仓单均核清后，按实际剩余仓位发起紧急市价退出。执行未知的退出单仍按原身份核对，不重复发送。
- 所有订单使用 `boz_` 前缀；下单前先持久化唯一编号。下单超时、执行未知、查询未找到都不会生成另一笔开仓单。原身份持续核对，直到交易所能够确认结果。
- 如果进程刚保存下单身份、尚未发送就崩溃，或者交易所长期无法查询原单，计划会保留并持续告警；这是有意保留的不确定状态。需人工核查原订单、成交及仓位后修复账本，不应直接删除状态文件重启。
- 账本采用临时文件、同步、原子替换保存，包含累计成交、活跃订单和冷却时间。文件锁防止同一本账本被两个进程同时使用。应仅运行一个实例，不要使用不同状态文件并行管理同一账户。
- 重启先恢复活跃计划和保护，再准备行情。损坏账本、未知版本或存在无账本的 `boz_` 挂单时拒绝继续新开仓。
- 正常退出尝试撤销开仓单、核对并发成交并补齐保护，保留交易所已接收的止盈止损。强制退出和网络中断无法保证完成清理；再次启动延续原计划。
- 该币的多空持仓在 Binance 上按方向合并，活跃计划期间不要手工或用其他程序交易同币。`closePosition` 会覆盖该方向全部持仓。

## 配置

`config.json` 提供默认配置，也可复制 `config.sample.json` 修改：

```json
{
  "keyfile": "/root/key",
  "kline_count": 12,
  "trade_mode": 3,
  "trade_usdt": 100,
  "trade_interval_seconds": 20,
  "entry_reprice_seconds": 1.5,
  "min_trade_interval_mins": 3600,
  "max_symbols": 2,
  "take_profit_rate": 0.03,
  "stop_loss_rate": 0.1,
  "min_move_rate": 0.3,
  "leverage": 1,
  "state_file": "data/state.json",
  "stale_price_seconds": 30
}
```

| 字段 | 说明 |
| --- | --- |
| `keyfile` | API key、secret 各一行；相对路径以配置文件目录为基准 |
| `kline_count` | 固定窗口根数，1～1500，包含当前 K 线 |
| `trade_mode` | 固定 3，表示双向；其他值拒绝启动 |
| `trade_usdt` | 每个方向的目标名义金额，按数量步进向下取整 |
| `trade_interval_seconds` | 选币扫描周期，默认 20 秒 |
| `entry_reprice_seconds` | 撤单重挂维护周期，默认 1.5 秒，最少 0.1 秒 |
| `min_trade_interval_mins` | **单位为秒**，沿用字段名；默认 3600 秒，0 表示无冷却 |
| `max_symbols` | 同时占用交易对数量上限，必须大于 0 |
| `take_profit_rate` | 独立方向止盈价格比例，0.03 表示 3% |
| `stop_loss_rate` | 独立方向止损价格比例，0.1 表示 10% |
| `min_move_rate` | 窗口振幅门槛，0.3 表示 30%，严格大于才选中 |
| `leverage` | 开仓前设置的交易所杠杆，默认 1，不改变名义金额预算 |
| `state_file` | 可写持久化账本，相对路径以配置文件目录为基准 |
| `stale_price_seconds` | WebSocket 行情过期限制，默认 30 秒 |

未填写的字段使用默认值。程序在启动时自动启用双向持仓；若账户当前存在不允许切换模式的持仓或挂单，启动失败。保证金模式沿用账户现有设置。

所有 REST 请求共享限速器，发送间隔至少 100ms，429/418 尊重 `Retry-After` 并退避。Binance 还有请求权重及订单次数限制，历史初始化、订单核对和保护会消耗请求额度；市场数量和 API 延迟较大时，维护周期可能长于配置值。启动时同步交易所时间，宿主机应保持正常校时。

## 构建和启动

本机运行：

```sh
go build -o boz .
./boz -config config.json
```

按 `boc` 的二进制只读挂载方式使用 Compose：

```sh
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -trimpath -o boz-linux-amd64 .
mkdir -p data
# 在部署机器准备 /root/key，并编辑 config.json。
docker compose up -d
docker compose logs -f boz
```

部署文件包括 `docker-compose.yaml`、Linux 二进制、配置和持久化 `data` 目录。Compose 使用 Alpine、自动重启和 45 秒退出宽限。密钥、配置及程序只读挂载，账本目录可写。保留同一份 `data` 目录才能在更新或重启后恢复订单和冷却。

## 验证

```sh
go test -race ./...
go vet ./...
```

测试通过本地 HTTP 服务模拟 Binance 回报，验证窗口滚动、撤单成交竞态、GTX 回退、未知回报不重复发单、全量保护、冷却持久化及请求限速。不会读取真实密钥或连接真实交易所。
